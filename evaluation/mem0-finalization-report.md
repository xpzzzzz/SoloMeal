## 真实 metadata 关联

沿用此前由用户确认的独立 Mem0 测试项目。本轮只读检查本地配置存在非空凭据、进程没有覆盖密钥，且配置文件时间不晚于此前实验的证据；项目隔离的依据仍是此前用户确认，并非仅靠文件时间证明。仅独立测试进程启用 Mem0，使用新建隔离 SQLite、随机合成账号和 Scripted 建议，不调用真实 Agent 模型。此前实验目录的未决操作预检未发现阻塞。

通过注册、登录、建议和确认 API 新建一条合成偏好。受限运行器在实际发送前校验服务端生成的规范 UUID 存于 `metadata.operation_id`，且不在消息正文；随后核对本地确认回执的 UUID、记忆 ID 和 `saved` 状态。真实 ADD 返回 `SUCCEEDED`，适配器随后读取单条详情，核验返回的记忆 ID、归属、结构化内容和 metadata UUID；回执与两次请求的关联一致，确认真实服务在本次读取时持久化并返回了 metadata。该结论基于本次单例，不能推断长期保留或列表一致性。

实际 Mem0 HTTP **8 次**，均为 200，无重试：ADD、写后 GET、删除前 GET、列表、删除内部 GET、DELETE、删除后列表、推荐中的搜索。按顺序的应用侧 HTTP 包装耗时分别为 **2719.606、507.005、528.738、500.187、509.806、682.964、478.394、518.225 ms**；受环境与单次样本限制，并非性能保证。配置中的 2 秒为 HTTPX 各阶段超时，非总墙钟上限。账户账单和本次实际费用不可得，费用为**未知**；未调用真实 Agent 模型。

删除前由应用核验该记忆 ID、归属、内容和本地 `active` 状态；仅删除本轮记录。删除后列表和搜索均为空，推荐 API 返回的候选没有记忆评分，本轮隔离库的 `unknown`、`pending`、`mutating` 操作合计 **0**。这些观察不证明服务端列表是完整一致快照，也不代表检查了历史用户数据。原始合成数据库、受限运行器和含合成记录 ID 的检查点留在本机任务输出目录，报告不包含密钥、认证头或记忆正文。

## 受控核销与人工处理

代码检查及已有 Fake Provider、MockTransport 和隔离 MySQL 证据表明：

- 从 `backend` 运行 `python -m app.commands.reconcile_memory --receipt-id <本地确认操作UUID>` 默认 dry-run，不访问数据库或远端；追加 `--apply` 才会读取指定回执及该回执所属用户的远端记录，并记录审计。该命令不接收任意目标用户参数，也没有公开 HTTP 核销接口。权限依赖主机登录及配置、数据库凭据的访问控制；应用没有单独的运维 RBAC。
- UUID、远端 ID、归属或内容不符，多候选、分页不完整、读取失败、远端列表不具权威性，以及历史缺少关联或槽状态变化时，不能把未知状态转为成功或未发送；不触发远端写入或重发。真实 Provider 始终不将分页结果标为权威。Fake 中的强证据转移只是模拟，不能推广为真实 Mem0 的能力。
- 审计仅保存操作者、UTC 时间、前后状态及固定分类和原因，不保存认证头、密钥或完整记忆文本。`--apply` 即使结果不确定，也可能为有效回执追加审计；不存在回执时没有可写的审计对象。重复执行保持一致状态，本轮新增测试覆盖 `saved`、`not_sent`、仍为 `unknown` 三种情形。

真实服务缺少证明分页为完整一致快照的契约；空搜索不能证明未写入，单条记录也不能证明唯一。因此真实未知写入继续屏蔽，禁止自动重发或直接解锁。需要时由获授权的运维人员保留本地回执及审计，核对操作 UUID、用户归属、已知事件或记忆 ID，并在受控环境检查服务商可用的独立证据；历史缺少 UUID 的记录、在途 `pending` 及更新/删除的不确定结果也须单独调查。现有命令无法根据普通列表把这些真实状态自动核销，若证据不足则继续保持屏蔽；本轮未自动处理任何历史真实用户操作。
