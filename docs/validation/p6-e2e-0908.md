# P6可重放浏览器E2E：断网、移动端、多用户与采购（2026-09-08）

承接第21节遗留的P6验收项。此前浏览器验收是逐次手工操作，只留下截图与结论；本轮把断网恢复、移动触摸、多用户切换和报价采购边界固化成可重放的 Playwright 场景，并把结果回归为代码断言。使用脚本模型夹具，未配置真实模型，未改动正式后端业务代码或迁移。

## 套件与环境

- 位置：frontend/e2e/（support.mjs + offline/shopping/mobile/accounts 四个场景文件），入口 `npm run e2e`（先构建 dist，再单并发跑 `node --test`）。package.json 新增 `e2e` 脚本与 playwright 开发依赖。
- 夹具：backend/scripts/browser_fixture.py 新增 `--data-dir`，由测试运行器指定 `frontend/.tmp-e2e/db-<port>`；每个场景文件在空闲端口起一个独立临时 SQLite 库，`/health/live` 就绪后再测，结束杀子进程并删除自己的目录，四个场景互不串库。
- 浏览器：Playwright chromium（先试 channel 再回退），`locale: zh-CN`；移动场景用 390x844、`isMobile`、`hasTouch`、DPR3 和真实 UA，并用 `matchMedia('(pointer: coarse)')` 自证设备形态。
- 断言边界：每页都挂 `pageerror` 收集器并断言为 0；文本断言读 `innerText` 而非可能为空的 `textContent`；断网用 Chromium `setOffline`，让 `navigator.onLine`、online/offline 事件与在途请求一起表现，而不是只关掉连接。

## 覆盖的场景

1. 运行中断网：脚本延迟6秒，在第一轮模型调用在途时断网 → 页面出现离线横幅与"连接中断，正在自动重连"，提示为中文可读文本；服务端仍只推进这一轮（API 读回 1 轮、1 条 get_inventory 事件、无第二个 run）；恢复后手动"继续执行"到 2 轮完成，工具记录不重复。
2. 离线横幅与自动同步：入库成功后断网，点刷新得到"浏览器已离线，恢复网络后可重试"，已加载批次仍可见；离线期间另一路 API 写入新批次，页面看不到；恢复网络后无人工点击即自动同步出新数据，横幅消失。
3. 双标签页叠加离线：A 页离线点"取消本次运行"不生效（服务端仍是 awaiting_confirmation，且未新增 run）；B 页在线确认入库；A 页恢复后收敛为"操作已确认/已入库"且不再提供确认按钮，库存只有 1 批 2 个。
4. 报价与采购丢包：对 `shopping/{id}/confirm` 用真实转发后丢弃响应的方式模拟"服务端已提交、浏览器不知道"；页面显示可读失败原因，服务端状态已是 completed 且只有 1 批 6 个；解除拦截后重试同一逻辑动作，收敛为"整单已入库"，不重复入库、不推进清单版本。
5. 采购离线保存：离线修改实际数量并保存被拒且草稿版本不变，恢复网络后同样的修改保存成功（版本 +1、数量 8）。
6. 手机纯键盘闭环：点按聚焦、逐字符键入、Tab 与 Enter 提交完成建号、录食材与批次（含到期日期）、保存偏好、保存包装报价；随后遍历 6 个标签页断言无横向溢出且没有高度 <40px 的可见按钮；退出登录后重新进入，从服务端读回偏好，证明不是内存残留。
7. 手机采购到做饭：报价 → 录入菜谱（含可选配料）→ 推荐缺料 → 保存方案 → 准备采购 → 用触摸键盘把整包建议 6.000 改成整数 8 → 保存草稿 → 两步确认入库 → 按最新库存更新方案 → 确认做饭扣 2 → 用餐记录撤销恢复 8；每一步都用 API 复核实际库存数量。
8. 多用户切换：甲账号手工入库加助手脚本入库共 2 批；同浏览器新建乙账号后库存页显示空状态、报价与采购页看不到甲的食材；乙的入库不影响甲；同一标签页退出并换登甲后，会话列表与库存换成了甲的数据且不残留乙的对话。

## 支撑这些场景的前端改动

- frontend/src/session.ts：新增 `NetworkError`（把 fetch 的英文 "Failed to fetch" 翻译成"浏览器已离线…"/"无法连接服务器…"）、`browserOnline` 与 `watchBrowserOnline`；离线时在发请求前就给出原因。
- frontend/src/main.tsx：登录页与主页共用的 `.offline-bar` 横幅，以及 online/focus/visibilitychange 触发的自动刷新；恢复网络后无需用户再点一次。
- frontend/src/sse.ts：`watchRun` 增加 `onConnection` 状态回调（connecting/connected/reconnecting/stopped）。
- frontend/src/AgentPanel.tsx：连接状态可读提示与手动重连入口，并在 online 时重新读取最新 run/session。
- frontend/src/style.css：`.offline-bar` 样式与窄屏下的可点按尺寸（触摸按钮 min-height 44px、复选框 20px、表头滚动区）。

## 限制

- 夹具是脚本模型 + 临时 SQLite，只证明前端在真实浏览器离线语义下的表现，不证明真实模型能力，也不替代 MySQL 后端证据；本轮未改后端与迁移，因此没有重跑 MySQL/原插件全量。
- 该套件目前只在本地执行，未接入 CI（需要额外安装 Playwright 浏览器并遵守既有动作固定 SHA 与 `ci-complete` 汇聚约定），因此不能称为持续回归。
- 断网使用 Chromium 离线仿真与单次响应丢弃，未覆盖弱网高延迟、DNS 失败与证书类故障；移动场景覆盖触摸键盘与常见窄屏，但仍不是各机型真机视觉验收。
- 未做真实模型、逐 token 输出、小票、生产部署与远程 CI；P6 与 P4/P5 整体仍为 IN_PROGRESS。临时账号（ui_off_*、ui_shop_*、ui_mob_*、ui_acct_*）只存在于临时库，凭据不写入文档；未提交、未推送。
