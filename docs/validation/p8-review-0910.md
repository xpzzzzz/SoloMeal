# P8 离线三模式评审入口（2026-09-10）

本段完成当前20调试场景的离线结构化/语义评审入口，不是统一冻结后的完整对照实验。新增 backend/scripts/review_agent.py，不读取.env、不访问数据库、不调用模型。

## 评审约定

- init 按显式试次目录建立不可覆盖的 manifest 和可填写的 review；绑定 attempt/report/call 文件逐字节 SHA256。score 核验试次清单、原始文件和有效 oracle，不能从已有清单删除失败，也不能替换报告。没有 report 的已启动试次仍保留为失败；后来补出 report 必须另建评审清单。尚未启动的计划试次由未来正式 cohort 执行器登记，本入口不冒充覆盖它们。
- intent、constraints、faithfulness 均需真实评阅者类型/名称及可解析的文件名、JSON Pointer、理由。安全/工具 objective_pass 不能独自令 Agent 任务成功；显式客观失败不能用语义评分覆盖。三项未齐为未评分，任一失败即语义失败。
- fixed_workflow 仅记录已知结构化意图下的客观参照，禁止填写自然语言语义/清晰度。direct_model 分别记录决策和任务，A010～12/A016/A019/A020写入预览执行、故障及取消闭环任务不适用，不据文字宣称执行完成。其他直接模型场景依语义评审判定决策任务。
- human_clarity 仅允许 kind=human 的真实评阅者填1～5整数；Codex/模型评阅不能代填。身份是评阅者声明，CLI不是身份认证系统。
- 原始确认扩展与场景任务分别记录；取消/旧库存扩展失败不能被评分覆盖。报告保留实际请求元数据、用量未知值、耗时及无效调用，不把无效调用数冒称参数非法数。
- 按试次保留版本/源码/模型参数，不汇总跨版本成功率。pool rate=null、P8 gate=incomplete。正式完整三模式重复、统一配置、统计分母、参数合法率与所有门槛聚合仍待 cohort 实现。

## A014 有界诊断设计

现有证据：v6/v7首请求分别31.083/31.032秒timeout，v8首请求24.221秒完成推荐（875输出token，其中853 reasoning），第二请求31.006秒timeout。三份timeout usage全部未知；三个失败wire哈希不同，不能称相同输入重试或推断根因。v8完整任务55.308秒，推荐保留忌口但没有最终回答。哈希和参数见上述绑定结果。

下一诊断版本命名 a014-timeout-probe-v1，最多两个无业务执行请求：

1. 先离线重建v8第二请求，必须同时匹配原messages/tools/wire三哈希；重建不符就终止，模型调用0次。不可用当前新输入假称重放；旧预算探针只重建v4第一请求，不直接套用。
2. 精确失败输入发送一次，仅探针客户端timeout由30改为60秒；1500输出token、模型、JSON v2、SYSTEM与不发送thinking保持不变，写新私有目录并记录独立配置。该60秒诊断不满足冻结30秒执行条件，结果不计正式得分，也不改.env/生产参数。
3. 若得到有效final，则停止，记录实际耗时、usage和语义；只有实际耗时超过30秒才支持“本次响应需要更长等待”。即使通过仍只是诊断，不能代替完整Agent A014闭环。若仍timeout/无效响应，仅允许一个短合成JSON final健康探针，同模型/1500/30秒且无工具，不把它当等价输入对照；之后停止并据诊断分类决定下一版本。
4. 不从超时推算费用，不因有限探针断言服务商故障或thinking根因。需要参数/提示变更时另版本、新目录；正式门槛保持不变。
