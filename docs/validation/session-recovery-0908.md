## 第一小段：注销与旧请求隔离

9月7日已新增sessionJson：请求发起前及响应body读取后核对登录代次与token，旧登录迟到401和成功结果均不能影响新会话。切换登录清空库存/菜谱/历史/方案/待确认缓存与重试key；旧refresh序号失效。AgentPanel卸载后停止后续自动advance和refresh，已在服务端执行的当前轮允许正常落库。

9月8日为夹具增加--model-delay（0～30秒，默认3）与两轮“测试查询”（get_inventory后文本完成）。仅脚本夹具可用，正式API没有测试开关。

浏览器实际验证：

1. 127.0.0.1:8010，独立临时SQLite，合成用户ui_sessions_0908。脚本延迟10秒。
2. 同一次浏览器调用连续执行：发送“测试查询中途退出”→看到运行中第1轮→注销→立即重登录。操作约0.72秒，早于模型延迟结束。
3. 等待当前模型轮结束后，从“我的对话”恢复原run，显示“可继续 · 已执行1轮”；没有自动执行第2轮，没有重复创建会话，新登录仍有效。
4. 库存保持0。注销不等于取消业务，用户可恢复或取消原run。

初次分散操作时模型已执行至第2轮，不能作为第一轮中断证据；改用连续操作后获得上述证据。一次自动定位使用AX增量树，未含注销按钮导致匹配失败，未执行注销；随后使用完整AX状态定位成功。

## 第二小段：续聊竞争与恢复入口

- 两个标签页用同用户各自登录，读取同一个已取消run及相同会话版本。
- 第一页发送“测试入库最终第一页”，第二页随即发送“测试入库最终第二页”。第一请求成功，第二页显示版本冲突且保留输入。
- 发现冲突后会话列表还是旧指针，原流程需要额外点击才能恢复。新增createRun错误后同步及“打开最新运行”按钮；旧历史run禁止续聊。读取最新run不重发消息。
- 最终构建复验：第二页冲突后出现“当前显示历史运行”，发送按钮禁用；点击“打开最新运行”直接看到第一页的当前run，输入仍保留，等待用户决定后续操作。
- 临时数据库只读核对：1个会话、5个按测试步骤产生的run；被拒的“测试入库最终第二页”消息记录数0，库存批次数0。最新run是awaiting_confirmation、1轮。
- 第二页取消待确认入库；第一页经SSE自动显示已取消并移除确认按钮。全程没有确认入库。
