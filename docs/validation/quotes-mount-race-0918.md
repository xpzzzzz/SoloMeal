# 2026-09-18 其它面板挂载 GET 竞态穷举与报价表单修复（第97节保留项处置）

## 结论

第96/97节修复偏好面板时明确保留了一项：「挂载即 GET＋回填输入」在其它面板是否同样构成竞态未穷举。本轮经用户授权按上一轮推荐做穷举，结论：**四个剩余组件中一处为真、三处排除**。

- **已排除（3）**：
  - `AgentPanel.tsx`：受控输入仅 `message` 文本框；挂载与焦点同步的 GET 只写 `runs/sessions/run` 三个列表/详情状态，任何响应路径都不回填 `message`（其 `updateRun` 另有 `event_seq` 单调门与 `active` 卸载门）。
  - `ReceiptPanel.tsx`：可编辑的 `Editor` 只在 GET `/receipts` 落地、`records` 非空后才首次挂载，挂载前页面无可输入内容，构成不了「先输入、后覆盖」窗口；`active` ref 另外守卫了卸载后的原图回填。
  - `InventoryEditor.tsx`：自身无挂载 GET（数据来自 App props）；`quantity/expires/source/location` 四个受控字段仅在用户主动选择批次时由 `select()` 回填，这是有意的选行行为而非响应覆盖。
- **确认并修复（1）**：`ShoppingPanel.tsx` 报价表单。表单 `key={selected+':'+(quote?.version||0)}`：已有历史报价的用户切到「报价与采购」，面板挂载 GET `/quotes` 在途时表单已可输入（key 为 `<id>:0`），响应落地后 key 变 `<id>:<version>`，React **重挂载整个表单**并把四个非受控输入重置为服务端旧值——与偏好面板同一竞态，只是机制是 key 翻转重挂载而非受控回填。该 key 的原始意图是「切换食材时重载默认值」，此语义只依赖 `selected`；`:version` 段的唯一额外效果就是本覆盖路径，故修复为净 1 行：`key={selected}`。保存后表单内容即用户刚提交的成功值、`expected_version` 提交时现取 `quote?.version`，均不依赖重挂载。
- **双向验证**：新回归 `frontend/e2e/quotes-race.test.mjs` 用门控 Promise 把面板挂载 GET 精确扣到输入完成后才放行（再叠 1500ms），修复版通过；`git stash` 还原旧 `ShoppingPanel.tsx` 重建后同一用例失败（数量输入被重置为服务端 `6.000`），恢复修复版重跑通过。用例同时断言保存 PUT 落库的是用户输入的 `8/7.20`，与第97节偏好回归同法钉死「输入存活→真实入库」。

## 调试过程中的一个真实更正

首版修复走的是 `loaded` 状态门控 key（`selected+':'+((loaded&&quote?.version)||0)`），新用例**仍然失败**——落地后 key 照样从 `:0` 翻到 `:1`。该中间版本被 React fiber 检查定位（`key=<id>:1`、输入被重置），据此把修复收敛为从 key 中移除 `:version` 段。最终净改动只有 1 行，中间版本未进入任何提交。
