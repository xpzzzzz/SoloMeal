# P9 受控弱网验收（2026-09-17，第87节）

## 范围与方法

在独立 Compose 项目（web/api 镜像 `p9-boundaries-0917`，Nginx 入口 18082）前挂自研故障注入代理
`deploy/weaknet_proxy.py`（监听 127.0.0.1:18083，控制端口 18084，转发到 18082），
实现两类可控故障并实测：

- **动态延迟注入**：`latency_ms` 按数据块实时读取，运行中可随时改，无需重启。
- **按请求断连**：代理按 HTTP/1.1 逐请求解析（含 Content-Length / chunked / SSE 帧），
  可对指定路径在服务端处理完成后、响应返回前关闭连接；同一 keep-alive 连接上的后续
  请求正常。`kill_count` 控制只杀前 N 个匹配请求。

控制接口：`POST /config`（改延迟/布防）、`GET /stats`（逐请求事件）、`POST /reset`。
所有脚本客户端使用 `trust_env=False`（环境代理会把被杀连接伪装成 502）。

## 结果

### 1. 延迟注入（API，httpx 实测）

| 场景 | 三次实测 |
|---|---|
| 基线（无延迟） | 0.009s / 0.010s / 0.010s |
| 注入 300ms | 0.622s / 0.620s / 0.629s |

注入后约 2 个 RTT（请求+响应各 300ms），与实现一致；数字为实测，非估计。

### 2. 做饭断连重试幂等（API）

对 `POST /api/v1/cooking`（Idempotency-Key `weaknet-cook-01`）布防杀死：服务端处理完成后
连接被杀，客户端收到 `RemoteProtocolError: Server disconnected without sending a response.`
（不是 502，证明杀的是真实连接）。同键重试返回 201 与同一记录
（id `183ff2ae-b037-4792-a3f2-e54f08fdd029`），库存保持 220g、活动做饭事件恰为 1：
断连期间业务只应用一次。

### 3. 撤销断连重试幂等（API）

对 undo 布防杀死：杀后库存 300g（撤销已生效但响应未送达），同键重试返回 200 同一记录，
活动做饭事件 0：撤销同样只应用一次。

### 4. 浏览器场景（经代理 18083，演示账号）

1. **断连错误显示**：布防 `kill_path=/api/v1/inventory` 后点击「刷新库存」，代理日志确认
   该请求被杀（0.619s，含 300ms 延迟 + 300ms kill_after），页面显示
   「无法连接服务器，请检查网络后重试」。同页其他请求（plans/recipes/cooking/ingredients）
   正常返回——按请求杀死不影响其他请求与同连接后续请求。
2. **清除布防后恢复**：`kill_count=0` 后再点「刷新库存」，错误消失，库存正常显示
   （大米 300 克、鸡蛋 2 个、0 餐）。
3. **刷新重登录恢复**：刷新页面进入登录页（页面本身提示「当前版本刷新页面后需重新登录」），
   重新登录后库存数据完整恢复。

浏览器场景以结构快照留证；早期一版代理只检查每连接首个请求，导致复用 keep-alive 的
浏览器流量绕过布防，已重写为逐请求解析并用同一连接实测验证（同连接第二请求被正确杀死）。
