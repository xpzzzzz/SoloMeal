# 可选的 Mem0 长期偏好

默认关闭。启用会把用户确认的结构化饮食偏好和服务端用户标识发送到 Mem0 托管服务；普通聊天、工具结果、库存与做饭记录不会发送。请在启用前了解服务提供商的数据处理方式和收费。使用单独的 Mem0 项目和密钥，不要提交密钥。

## 配置与使用

1. 在 Mem0 Platform 创建项目和 API key。在 `backend/.env` 中设置 `SOLOMEAL_MEM0_ENABLED=true`、`SOLOMEAL_MEM0_API_KEY=<密钥>`；可选 `SOLOMEAL_MEM0_TIMEOUT_SECONDS=2`（每次 HTTP 请求，范围 0～10 秒，不含 0）。关闭或没有密钥时不发请求。部署 Compose 时将同名变量写入其部署环境文件并重建 API；不要将密钥提交到仓库。当前运行环境不会自动更新。
2. 自然语言提议需要现有 Agent 已启用并配置其模型。说出明确的长期偏好，例如「以后喜欢清炒」；助手可能提出一条建议，检查后点击确认。建议本身没有保存。认证接口 `/api/v1/me/memories/confirm` 校验该用户的运行、步骤和建议内容；`/api/v1/me/memories` 提供查看、修改和删除。目标用户始终来自登录会话。原先自由新增入口已取消。
3. 首页、推荐 API 和 Agent 的推荐工具检索当前用户记忆，在现有评分后叠加有限的软偏好。关闭个性化会跳过检索。业务写操作与方案版本校验使用原有规则，不在事务锁中调用 Mem0。

第一版仅支持食材名、菜谱 `cooking_methods` 的精确值、以及估算时间的分钟上限。时间仅作为软倾向；过敏或忌口应继续设置为原有硬限制。当前没有可靠的结构化口味或菜系字段，因此不推断这类偏好。记忆与菜谱字段不完全一致、模型未提出建议、或者缺少明确长期措辞时可能不会生效；确认前用户应核对类别、对象及方向。相同对象的相反记忆会被忽略直至纠正；重复记忆不会放大得分。有显式收藏或喜欢/不喜欢反馈的候选跳过记忆加分，避免叠加。每个候选的记忆分限制在 -6 到 +6；匹配理由随结果返回。

Mem0 采用 v3 `add`、`search` 和分页列表，以及 v1 单条 `get`、`update`、`delete` REST 接口；依赖复用 `requirements.lock` 中的 `httpx==0.28.1`，无需 Mem0 SDK 或自建向量数据库。写入采用 `infer=false`，将已确认的结构化记录直接导入，不调用 Mem0 的聊天提取流程；服务端可能仍有嵌入或检索成本。读取只接受拥有正确用户标识和 SoloMeal schema 的记录。对于响应中缺失用户标识的条目，适配器逐条核验归属，受查询结果数量、分页数量和请求间时间预算约束；未能核验时管理列表明确报错。检索最多取 100 条，分页管理最多 1000 条。HTTPX 的网络阶段超时和请求间预算并非严格的端到端墙钟上限。

确认幂等及偏好状态复用现有 `operations` 表：短事务保留确认记录与语义状态并提交，远端调用期间不持有该事务锁。同一建议及同义建议不会重复发起新增；更新或删除先持久化本地抑制，再处理远端同义副本，防止滞后的旧结果参与后续推荐。远端请求失败、超时或进程中断可能留下未知或待处理状态，系统不会自动重发，该语义将被屏蔽。请和业务数据库一起保留 `operations` 表；数据库恢复或切换 Mem0 项目后需对账。已获取旧快照的在途推荐可能在删除完成后仍返回旧排序。真实服务读写和索引可见性已做有限冒烟，其一致性和延迟范围尚未充分验证。

新确认携带随机操作 UUID 到远端 metadata，并在本地确认回执中保留关联；成功还需单条读取核实归属、内容和 metadata。仅受信任的主机运维人员可从 `backend` 目录运行 `python -m app.commands.reconcile_memory --receipt-id <本地确认操作UUID>` 查看无访问的 dry-run；添加 `--apply` 才实际读取指定本地记录和远端信息并记录审计。命令依靠主机账户及数据库/密钥访问控制，不提供 HTTP 核销接口。当前 Mem0 Provider 对分页没有强一致快照证明，即使发现看似唯一记录也保留未知，空列表更不代表未写入；历史无关联标识、待处理状态和变更冲突必须继续人工调查，不得自动重发或直接解锁。详细限制见 [未知写入核销报告](../evaluation/mem0-unknown-write-reconciliation-report.md)。

第四阶段补测：更新或删除前，明确不存在或属于其他用户的记忆统一返回 404；初始归属读取或预留后的列表读取失败时返回不同的 503，不把这些只读失败记为未知写入。其他远端数据矛盾仍可能保守地保留未知状态。更完整的实测边界、延迟及尚未实现的对账方案见 本地保留的真实冒烟报告（含测试标识及环境路径，不随此提交发布）。
