## 三分钟演示脚本

事前在独立演示项目按[部署指南](../deploy/README.md)启动并运行demo.py seed，另上传一张合成小票保留为未确认草稿供编辑演示（seed中的票已确认）。凭据从本地私有credentials.json读取，不投屏展示。使用合成账号和小票，不展示真实用户图片或模型密钥。现有18080可继续供用户试用，演示无需改动它。演示前预演一次并确认库存。

| 时间 | 页面与操作 | 讲解重点 |
| --- | --- | --- |
| 0:00～0:25 | 登录，查看库存和剩余量 | 面向一个人的日常厨房，按克/毫升/个管理批次；不是旧插件的近似菜份 |
| 0:25～0:55 | 菜谱页按时间、厨具和份数推荐 | 硬约束由服务端校验，库存不足时列补购；未知价格不冒充满足预算 |
| 0:55～1:25 | 选当前可做菜，查看预览，点击确认做完 | 先预览再确认，事务扣减实际批次；展示库存前后变化 |
| 1:25～1:45 | 用餐记录撤销，再刷新 | 按实际消耗恢复，重复请求的幂等键避免重复扣/加 |
| 1:45～2:15 | 打开合成小票草稿，展示可编辑字段及单位错误提示 | 视觉输出只是草稿，数量/单位核对后才能整单入库；勿重复确认seed已完成的小票 |
| 2:15～2:40 | 打开助手历史运行与工具过程 | 单Agent有只读工具与确认状态机；模型关闭时明确降级，库存功能继续可用 |
| 2:40～3:00 | 展示部署/测试与失败摘要 | 本地恢复和工程测试有证据；合成留出48/60，未达到85%，不能声称全部验收通过 |

使用模型关闭的演示环境时，助手展示关闭状态和已有历史即可。若要演示新的真实模型运行，应另设明确配置与有界流程，记录请求和失败；不要启动任何旧评测批次，不把脚本模型画面称为真实模型效果。网络失败时保留画面并说明刷新/重试路径，不通过换成功片段隐藏失败。

## 技术问答

**为什么保留一个Agent？** 任务主要是查询、规划和经确认后的单用户事务；显式状态机、租约与持久事件已足够表达当前流程。没有为了框架名称引入多Agent或LangGraph。

**模型能直接改库存吗？** 模型提出受schema和身份约束的工具请求。写入先生成待确认内容，由用户确认后进入服务端事务；模型正文不能授权业务DML。

**为什么模型算对了也不一定通过评测？** 任务契约、必要查询、参数、硬约束、后续建议和写入结果分别检查。旧A026存在题干与执行oracle差异，旧失败保留；后续独立采购协议另记版本。

**如何处理并发和重复点击？** 用户/请求绑定幂等键，版本检查、短事务与批次锁保护修改；MySQL竞争用例已单独验收。SQLite测试不作为真实锁语义证据。

**网络断开会重复执行吗？** SSE事件游标用于恢复展示，数据库运行状态与幂等键保护业务重试；错误时查询当前状态。受控弱网下做饭/撤销幂等重试、真实Agent的API/SSE及浏览器断线恢复已验证，见[浏览器报告](validation/p9-agent-ui-weaknet-0917.md)。人工failed/retry、长离线等路径仍未在该批真实模型场景覆盖。

**如何避免编造报价？** Agent不能提交quotes；报价来源与日期从已保存记录取。estimate_purchase处理口述缺口，按整包装报价估算，不猜份数、不自动采购。

**推荐说明来自哪里？** 当前recommend_meal出口的产品展示按工具结果生成，原模型文字另行留证。这提升展示一致性，不等于模型语义泛化提升。

**如何限制成本与请求？** 单run步数、模型超时/输出预算、视觉每日次数，以及Nginx入口限流。尚未实现全局账单预算、多节点统一账号限额和完整并发连接配额。

**备份为什么同时包含图片？** 小票行与私有原图是关联数据。维护窗口停止应用写入后联合导出SQL和图片，manifest哈希校验后仅向全新空目标恢复。部分恢复失败目标保留检查，不能强行覆盖重试。

**目前能公开宣称什么？** 定量库存、显式确认、MySQL幂等/竞争验证、本地联合恢复，以及指定配置的小票验收。合成留出Agent48/60（80%）未过85%门槛；最新诊断是已暴露回归，不能替代盲测。
