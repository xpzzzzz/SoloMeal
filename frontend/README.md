# SoloMeal frontend

React + TypeScript + Vite。当前连接真实后端，包含登录/注册、食材种类与批次入库、菜谱录入、单餐只读推荐、做饭确认、撤销历史和厨房偏好。

在本目录执行：

```powershell
npm ci
npm run dev
npm run build
npm test
npm run e2e
```

访问http://127.0.0.1:5173，API代理至127.0.0.1:8000。先按../backend/README.md启动后端和专用数据库。
首次创建自己的账号，然后添加食材/批次、设置厨具、添加菜谱、生成推荐。
数据为空时展示真实空状态，无自动导入演示食谱。

登录令牌仅保存在内存，刷新需重新登录。入库重试和做饭确认复用幂等key；页面状态不持久化，未确认的请求结果需重新发起或从运行列表恢复。
推荐只读不预留库存；保存后可更新方案版本并按方案人数确认做饭。独立菜谱按钮按原菜谱人数。
库存盘点已实现，小票待做。不要把构建通过当成功能全量验收。

新增一人食助手：模型配置后可工具对话，确认保存提案，查看工具轨迹，从运行列表恢复；见../docs/agent.md。

SSE状态流支持认证、游标重连与去重，并向界面暴露连接状态；npm test运行15项分片/重连/登录代次/离线原因测试，已接CI。

库存页可盘点数量和勾选常备；菜谱页可添加可选配料、选择本餐是否使用，并幂等导入3道原创示例。

`e2e/` 是真实浏览器套件：`npm run e2e` 先构建dist，再用Playwright chromium按空闲端口各起一个隔离脚本夹具（../backend/scripts/browser_fixture.py，临时SQLite，仅127.0.0.1，不是生产服务也不是真实模型），断言断网恢复与自动同步、离线标签页取消后收敛、采购确认丢包重试、390窄屏纯键盘录入与报价→采购→做饭→撤销、双账号隔离与换登清缓存。截图写入被忽略的 `.tmp-e2e/`。该套件目前只在本地执行、尚未接入CI，也不替代后端MySQL证据；见../docs/validation/p6-e2e-0908.md。
